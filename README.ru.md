# srvmon

**Видеть, что происходит на сервере — на самой дешёвой VDS, какая у вас есть.**

Одна страница: какие сайты работают, куда ушёл диск, какая база растёт, какой
сертификат истекает на следующей неделе, какая служба упала в три часа ночи.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/dmitry575/srvmon/main/install.sh | sudo bash
```

Всё. Установщик скачает последний релиз, создаст сертификат и пароль, поставит
две службы systemd и напечатает адрес:

```
══ Готово ══

  Адрес:  https://203.0.113.10:8452
  Логин:  admin
  Пароль: Kf3nQ8xTr2mWpL9dVe
```

Открываете адрес, входите — и всё. Ничего больше вводить не нужно: ни обратного
прокси, ни записи в DNS. Сертификат самоподписанный, поэтому браузер один раз
спросит, доверяете ли вы ему.

## Зачем она

VDS за 300 рублей в месяц: два ядра, четыре гигабайта, три-четыре ваших сайта.
Хочется понимать, что там происходит. Что есть сегодня:

| | Сколько ест | Настройка | Подходит одной машине? |
|---|---|---|---|
| **Grafana + Prometheus + экспортеры** | 400 МБ – 1 ГБ | часы, три службы, свой язык запросов | рассчитано на парк машин |
| **Zabbix** | от 1 ГБ, нужна своя база | день, агент, сервер, фронтенд | рассчитано на парк машин |
| **Netdata** | 150–300 МБ | одна команда | силён в метриках, но не знает про *ваши сайты* |
| **Панели хостинга** (cPanel, ISPmanager) | тяжёлые, платные, со своим уставом | хотят владеть машиной | заменяют вашу настройку собой |
| **srvmon** | **~60 МБ, два процесса** | **одна команда** | **ради этого и сделана** |

srvmon не пытается быть платформой мониторинга. Она отвечает на десяток
вопросов, которые реально задаёшь про маленький сервер, и не мешает жить.

### Почему она лёгкая

* **Без зависимостей.** Только стандартная библиотека Python: ни pip, ни
  виртуального окружения, ни сборки фронтенда. Интерфейс — три файла как есть.
* **Два процесса.** Веб-часть и сборщик, примерно по 30 МБ.
* **История в SQLite**, несколько мегабайт, чистится сама.
* Писалась на машине с двумя ядрами и 3,8 ГБ памяти, рядом с боевыми сайтами,
  за которыми и следила. Будь она тяжёлой — мешала бы им.

## Что показывает

| Раздел | На какой вопрос отвечает |
|---|---|
| **Обзор** | Сервер жив? Процессор, память, подкачка, диск, очередь задач, сеть, аптайм — и сразу все сайты, базы и предупреждения |
| **Домены** | Какие сайты работают, как быстро, сколько запросов, сколько ошибок, когда истекает сертификат **и регистрация домена** |

| **Диск** | Куда ушло место — по разделам, по каталогам, с просмотром только на чтение |
| **Службы** | Юниты systemd: состояние, память, порты, аптайм, число перезапусков, хвост журнала |

| **События** | Что сломалось, когда и когда вернулось |

## Добавить свои сайты

Само по себе ничто под наблюдение не попадает: на машине с десятком виртуальных
хостов такой список был бы бесполезен. Вы добавляете то, что важно, в разделе
**Settings**, и сборщик подхватывает это без перезапуска.

Посмотреть, что на сервере уже есть:

```bash
python3 /opt/srvmon/tools/discover.py
```

Инструмент покажет имена серверов nginx, прикладные службы, слушающие порты,
базы MySQL и PostgreSQL, файлы SQLite — как подсказку для формы, а не как
готовое решение.

Для каждого сайта заполняются: домен, каталог проекта, журналы nginx, путь к
сертификату, юнит systemd, порт бэкенда, база. Обязателен только домен.

## Что нужно

* Linux с systemd
* Python 3.8+ (пакеты не нужны)
* `openssl` — только чтобы создать самоподписанный сертификат
* nginx — необязательно, чтобы читать трафик каждого сайта из его журналов
* MySQL/MariaDB, PostgreSQL, SQLite — необязательно, в любом сочетании

Проверено на Ubuntu 24.04. Должно работать везде, где есть systemd и свежий
Python.

## Способы установки

```bash
# обычный
curl -fsSL https://raw.githubusercontent.com/dmitry575/srvmon/main/install.sh | sudo bash

# другой порт, другой логин
curl -fsSL .../install.sh | sudo bash -s -- --port 9000 --user bob

# закрыто: слушать только 127.0.0.1, ходить через туннель SSH
curl -fsSL .../install.sh | sudo bash -s -- --local
#   ssh -L 8452:127.0.0.1:8452 вы@сервер   → http://127.0.0.1:8452

# из клона, если хочется сперва почитать код
git clone https://github.com/dmitry575/srvmon.git /opt/srvmon
cd /opt/srvmon && sudo ./install.sh

# убрать службы, собранные данные оставить
sudo /opt/srvmon/install.sh --uninstall
```

Если вместо адреса хочется свой домен, в `nginx.example.conf` лежит готовый
блок с Let's Encrypt и ограничением попыток входа. Тогда ставьте с ключом
`--local`, чтобы сама панель осталась на localhost.

### Команды

```bash
systemctl status srvmon srvmon-collector
systemctl restart srvmon srvmon-collector
journalctl -u srvmon-collector -f
python3 /opt/srvmon/tools/passwd.py admin     # сменить пароль
```

## Безопасность

Панель видит много, поэтому нарочно почти ничего не умеет.

* **Только чтение.** Ни команд, ни произвольного SQL, ни записи файлов, ни
  удаления, ни `systemctl` из веба. Она скажет, что служба упала, но поднять
  её не сможет.
* **Пароль** хранится хешем PBKDF2-HMAC-SHA256, 240 000 итераций. Сессия —
  случайный токен в cookie с HttpOnly и SameSite=Strict.
* **Она отказывается слушать внешний адрес без TLS** — пароль открытым текстом
  не тот размен, который стоит предлагать.
* **Пароли баз не хранятся.** MySQL читается системным клиентом через
  `/etc/mysql/debian.cnf`, PostgreSQL — через `psql` от пользователя
  `postgres`.
* **Просмотр каталогов** ограничен белым списком, разворачивает символические
  ссылки до проверки, не читает содержимое файлов и помечает известные имена
  с секретами.
* **Командные строки процессов маскируются**: после `password`, `token`,
  `secret` или `api_key` подставляется `***`.
* **Демонстрационный режим** подменяет имена, адреса и пути в ответах API — и
  снимок своей панели можно опубликовать, не публикуя свою инфраструктуру. Все
  снимки в этом файле сделаны именно так.

Нашли уязвимость? См. [SECURITY.md](SECURITY.md).

## Чем она не является

Сказать это прямо — сэкономить всем время:

* **Не панель хостинга.** Не создаёт сайты, пользователей, почтовые ящики и
  базы, и не трогает ваш конфиг nginx. Она смотрит, решаете вы.
* **Не платформа мониторинга.** Один сервер, ваши сайты. Никаких агентов,
  кластеров и конвейеров оповещений — хотя предупреждения есть, а канал
  доставки подключается одной функцией.
* **Не просмотрщик логов.** Читает хвост журналов ошибок, а не гигабайты
  истории.

Если нужно что-то из этого — перечисленные выше инструменты делают это хорошо.
srvmon для случая, когда они дороже, чем машина того стоит.

## Откуда берутся цифры

Всё измеряется на самой машине. Если что-то нельзя измерить при текущей
настройке, панель так и говорит, а не подставляет правдоподобное.

* **Система** — `/proc` и `statvfs`, напрямую.
* **Трафик сайтов** — журналы nginx: читается только прирост с прошлого раза,
  ротация переживается.
* **Время ответа** — собственные проверки панели по HTTPS, а *не* журналы: в
  формате combined поля со временем нет, и взять его оттуда честно неоткуда.
  Если в вашем формате оно есть, парсер подхватит `rt=`/`urt=` сам.
* **Базы** — `information_schema` для MySQL; `pg_stat_*` и `pg_*_size()` для
  PostgreSQL; `PRAGMA` и `dbstat` для SQLite, открытой только на чтение в
  режиме immutable, чтобы не помешать пишущему сайту.
* **Сертификаты** — живое рукопожатие TLS плюс файл на диске: обновлённый, но
  не перечитанный сертификат виден сразу.
* **Срок регистрации домена** — прямой запрос WHOIS раз в 12 часов.

Интервалы сбора — от 20 секунд для системных метрик до 12 часов для WHOIS, все
правятся в настройках. История высокого разрешения хранится 7 дней, часовые
точки — 180 дней.
